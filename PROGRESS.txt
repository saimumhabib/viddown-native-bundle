FINDINGS THAT CHANGE THE PLAN
 1. CPython's own android.py downloads PREBUILT OpenSSL/libffi/bzip2/xz/zstd/sqlite from a third party
    (beeware/cpython-android-source-deps releases). That violates the from-source rule.
    Decision: build OpenSSL + libffi from source ourselves (using that project's published patches,
    vendored with provenance) and pre-create the prefix so android.py skips the download.
    bzip2/xz/zstd/sqlite are NOT built (yt-dlp does not need them).
 2. yt-dlp now needs an external JavaScript runtime for some sites (yt-dlp-ejs). NOT solved yet.
    Candidate: QuickJS from source. Decision needed (Phase 7).
 3. brotli and pycryptodomex need native compilation: deferred.
 4. CPython's own CI covers only arm64-v8a and x86_64; armeabi-v7a/x86 are experimental in the matrix.
 5. python.org, ffmpeg.org, openssl.org, git.ffmpeg.org, sourceware.org are unreachable from the dev
    sandbox: those source entries are UNPINNED until the update-sources workflow pins them from Actions.
 6. The Android SDK/NDK is a Google-provided toolchain (not shipped): documented exception.

FIRST CI RUN (2026-10-27) - RESULT AND FIX
 - All ABIs failed in build_python.sh at 'cross-build/build' configure: "cannot run C compiled programs".
   Cause (my bug): android-env.sh was sourced in the top-level shell, so CPython's BUILD-machine Python
   (which must run natively) was configured with the Android cross clang. The clang message
   "-print-multi-os-directory" is a harmless probe warning, not the cause.
   Fix: top-level shell stays clean (cross variables are unset); every step that needs the NDK toolchain
   loads android-env.sh in its own subshell; configure-build/make-build run first in the clean env.
   Verified here: `android.py configure-build` on the pinned CPython 3.14.10 source in a clean env succeeds
   (gcc, "cross compiling... no"). make-build was started but not waited out (slow sandbox): NOT verified.
 - Still unverified: OpenSSL/libffi/CPython host steps, FFmpeg, packaging of real outputs, smoke test.

FOURTH CI RUN (2026-10-27) - RESULT AND FIX
 - x86_64 emulator smoke test reached the yt-dlp download step. The FAIL lines reported were: download,
   merge, cancel, plus "/system/bin/sh: syntax error: '(' unexpected". Cause (my bug): two commands sent via
   `adb shell` contained an unquoted `%(ext)s`; the device shell parses the string and rejects "(".
   The merge and cancel FAILs were consequences (no dl.mp4 to merge, the background yt-dlp never started).
   Fix: literal -o file names (dl.mp4, slow.bin). Verified on host with real yt-dlp 2026.10.21: download
   writes the file, -J returns formats, kill-by-PID cancel logic works.
 - The FAIL list did not include the python/ssl, yt-dlp --version, ffmpeg/ffprobe start or `-J` checks;
   they probably passed, but the PASS lines were not seen, so this is NOT confirmed.
 - Checked and ruled out: HEAD on the slow fixture returns 404, but yt-dlp still starts the GET download.
